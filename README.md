# 回解 · 算法竞赛错题复盘

个人使用、本地存储的 Codeforces 错题复盘系统。导入公开提交，保留失败题目，记录错因和代码，通过多轮独立重做检验掌握程度。

## 在线使用（GitHub Pages）

访问 **https://lllllei073.github.io/contest-review/**，无需安装 Node.js 或启动后端。输入 CF handle 即可导入公开历史。

- 在线版将数据保存在**当前浏览器的 IndexedDB**；笔记、代码和备份不会上传到 GitHub。不同浏览器、设备和站点地址的数据不会自动同步。
- 清除网站数据、使用隐私模式或更换设备可能导致本机记录不可用。请定期导出 JSON 备份；已有本地版备份可直接导入。
- 使用支持 IndexedDB、WebAssembly、Web Locks 的现代 Chrome、Edge、Firefox 或 Safari。为避免覆盖，另一个标签页使用错题库时会提示关闭它后刷新。
- 官方 Codeforces API 支持 CORS，浏览器直接请求，无中转服务器、密码或密钥。同步期间需保持页面打开，重开后可继续核对已保存的分页。
- 首次打开并完成页面缓存后，支持离线刷新、编辑和复习；CF 同步仍需要网络。
- 恢复前自动备份保存在浏览器中，可在设置页下载**最近一次恢复前的备份**。

本地预览在线版：

```powershell
npm ci
npm run build:pages
npm run preview:pages
# 打开 http://127.0.0.1:4173/contest-review/
```

Pages 使用 Hash 路由，详情链接刷新不会 404。构建默认路径 `/contest-review/`，更换仓库名时通过 `PAGES_BASE_PATH` 修改；浏览器数据库按站点路径隔离，改域名或路径之前应导出备份。

### 自动发布

`.github/workflows/pages.yml` 在推送 `main` 时执行类型检查、核心测试、本地版和浏览器版完整流程测试，全部通过后发布 `dist-pages`。GitHub 仓库的 Settings → Pages → Source 使用 **GitHub Actions**。线上版本仅含静态资源，不打包服务器代码、测试账号或本地数据库。

## 本地 SQLite 版启动

需要 **Node.js 24 或更新版本**（使用内置 `node:sqlite`；本项目在 Windows / Node.js 26 上验证）。

Windows 双击 `start.cmd`，等待安装依赖和构建完成，在浏览器打开 **http://127.0.0.1:3210**。终端窗口需保持运行，按 Ctrl+C 关闭服务。首次安装需要网络，安装后可离线编辑与复习。

也可以在项目目录运行：

```powershell
npm ci
npm run build
$env:NODE_ENV = 'production'
npm start
```

开发模式：`npm run dev`，浏览器打开 http://127.0.0.1:5173。前端代理 API 到 3210 端口。可通过 `PORT` 修改后端端口；开发代理需相应修改。`DATA_DIR` 可指定数据库目录，默认 `data`。

## 第一次使用

1. 打开「设置与数据」，输入自己的 Codeforces handle 并绑定。新用户名需要联网验证，已有账号可离线切换。
2. 点击「开始首次同步」。系统分页读取全部公开历史，同步期间可继续浏览，界面显示已读取条数。当前用户数据尚未导入完整前，不进行增量截断。
3. 打开「错题库」，选择题目，填写错因、当时的思路、正确解法、复杂度和反例，按需粘贴代码。
4. 点击「完成复盘」，下一天进入复习。重做之后记录结果、耗时和新发现。
5. 定期在「设置与数据」导出备份。更换电脑或浏览器时，打开在线版或安装本地版后恢复备份。

### 同步口径

- 只读取官方公开 API，无密码、无 API 密钥。不会抓取完整题面、题解或源码；使用原题和提交链接，代码手动粘贴。
- WA、TLE、MLE、RE、CE、部分得分、被 hack、空闲超时和安全违规结果视为明确失败。待判、系统错误和未知结果不自动纳入。
- 失败过的题目会保留。后续 AC 更新解题状态，不删除复盘，不自动标记掌握。全量重新核对可能因历史重判更新 AC 状态，但不会删除曾经建立的复盘记录。
- 按提交 ID 去重、按比赛 ID 和题号归并。重复同步不会覆盖笔记、重做记录或忽略标记。仅有练习提交不会显示成正式参赛。
- 首次全量导入；之后点击「增量同步」获取新记录并刷新最近一段记录和历史待判记录。较早已终判提交的重判，用「全量重新核对」更新。
- 官方 API 请求全局串行，间隔至少 2.1 秒，每次请求 20 秒超时，最多三次尝试。同步失败或应用关闭后保留完整分页，下次继续时从头去重核对，以免期间新增提交导致分页错位。
- 比赛和题库信息暂不可用时，已经导入的提交仍可使用；页面会明确提示信息补全部分失败。
- 关联比赛的通过题数指现有提交记录中曾 AC 的题目，不是比赛现场成绩。评级排名使用官方评级结算记录。
- 账号切换使用独立分区。Codeforces 改名不会自动合并旧分区。

### 复习规则

- 初次完成复盘：下一天重做，阶段为 0。
- 第 1 / 2 / 3 / 4 次独立做对：分别间隔 3 / 7 / 14 / 30 天再做。
- 第 5 次独立做对：标记「已掌握」，退出到期队列。
- 借助提示：保持当前阶段，下一天再做；仍未做出：重置阶段，下一天再做。
- 到期列表按本地日期计算，包含逾期题目。可手动修改复习日期；已掌握题可重新加入复习。
- 忽略题目会移出待复习和题目统计，但不删除记录；在错题库「已忽略」中可以恢复。
- 统计按唯一题目计数，同一题多个算法 / 错因可分属多个分类。提交总数与重做次数单独统计。

### 笔记

支持 Markdown、`$行内公式$` 和独立 `$$` 公式块，代码留档支持 C++、Python、Java、JavaScript、Rust、Go。禁用 Markdown 原始 HTML，代码仅展示，不执行。

## 本地 SQLite 版数据与备份

- SQLite：`data/review.sqlite`，启用 WAL；运行期间不要仅复制主数据库文件，应使用应用内导出。
- JSON 备份带 `format`、`version`，包含全部账号、题目、提交、笔记、代码、重做记录和同步状态。
- 恢复前进行结构、版本、唯一性和关联校验，失败不改动数据库。恢复上限 100 MB。
- 恢复是**整体替换**；执行前页面会明确提示，并将现有数据自动保存到 `data/backups/before-restore-*.json`。写入在单一事务内完成。
- 同步期间禁止恢复、导出和账号切换。服务默认仅绑定 `127.0.0.1`，写接口校验 Origin 和应用标识；这是本地单用户应用，不用于直接公网部署。

## 开发与验证

```powershell
npm run check       # 前后端类型检查
npm test            # 同步、复习、备份、API 等固定样例测试
npm run build       # 类型检查 + 前端生产构建
npm run test:e2e    # 浏览器完整操作流程，使用测试专用 CF 固定数据
npm run build:pages # 构建 GitHub Pages 在线版及离线缓存
npm run test:pages  # 浏览器存储版完整流程、旧备份兼容、离线和多标签页测试
npm run check:cf    # 真实 CF 只读连通性验证，默认 tourist，仅取 10 条提交
```

首次运行浏览器测试若缺少浏览器：`npx playwright install chromium`。E2E 使用临时独立数据库和 3211 端口，不写入正式 `data` 目录，生产服务不包含模拟 CF 接口。真实 API 检查仅使用内存数据库，不绑定正式账号。

代码结构：`src` 为 Vue 界面，`src/browser` 为浏览器数据入口和 IndexedDB 适配；`server` 为本地 Fastify 和 SQLite 适配；`shared` 为两种运行方式共用的数据规则、校验、CF 同步和复习逻辑；`tests` 为固定数据自动化验证。在线版使用 sql.js 在浏览器运行相同的数据模型，再将数据库保存到 IndexedDB，数据库升级由 `PRAGMA user_version` 管理。

首版不包含 AI、多用户服务、云同步、在线运行代码或私有 Gym 授权。完整历史导入的耗时取决于提交量和 Codeforces 响应；不能预先显示准确总条数。
