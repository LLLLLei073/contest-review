# 训练工作台全功能重构 Implementation Plan

> 状态：第二版已获用户确认，2026-10-18 开始实施。视觉方向为「清爽专业的训练工作台，保留少量科幻特色」，完整范围包含 ReAct、BKT、先修学习路径与预算规划算法。
> 执行指引：确认后按 Task 顺序推进，沿用 executing-plans 的逐项实现与验证方法。本轮不默认提交、推送或发布。

**Goal:** 在保留全部原有能力与历史数据的基础上，让每项功能至少获得一项可感知的实用改进，统一视觉，并通过 ReAct 引导复盘、知识追踪、先修路径规划与预算约束排课形成可追溯的高效训练闭环。

**Architecture:** 保留 Vue 3 + Fastify/SQLite 与 Pages/sql.js/IndexedDB 双运行方式。业务判断和规划算法放在 shared，ReAct 复用现有 LangChain/星澪工具循环；确定性规划引擎可离线运行，AI 解释和交互辅导按需使用。新持久化记录统一纳入 v11 备份并兼容 v1–v10，新增接口必须两端同义实现。

**Tech Stack:** Vue 3、TypeScript、Vue Router、Lucide、Fastify、SQLite/sql.js、现有 LangChain 服务、Node test、Playwright、Vite。

本次审查以当前源码为准：10 个页面组件、8 个主导航入口。题目详情和模拟赛是辅助页面。早期 experience.md 中的「六个主入口」已与当前代码不一致，验收文档需一并更新。

- `ProblemDetail.vue` 742 行、`Settings.vue` 733 行、`Contests.vue` 671 行；优先拆分独立业务区域，保留页面对草稿和选择的所有权。
- 错题筛选仅部分字段从 query 恢复；补齐搜索、平台、算法、错因、难度、状态及分页的 URL 往返。
- 知识图谱绘制 `graphNodes.slice(0, 40)`；改为可检索的聚焦子图，明确显示当前范围与总量，并提供完整列表入口。
- 训练、统计、知识、助手之间已有数据联系，但操作入口分散；通过统一的下一步操作与证据导航连起来。
- `shared/agent-service.ts` 已有 `createAgent` 模型/工具循环、6 次外层模型调用、12 次工具调用和 3 分钟截止时间。此次 ReAct 的增量是面向学习复盘的状态、证据反馈和用户检查点，不另建重复的智能体。
- `shared/knowledge.ts` 已有知识卡 `prerequisites`；学习路径复用并核查这些先修关系。现有新知选择以领域分数、难度与周目标覆盖为主，未来题单部分调整还依赖模型选题；本次新增可离线、可解释的算法决策层。

方案取舍：

1. **推荐：保留数据内核，逐模块重构工作流。** 能同时改进实用性、审美和维护性，每阶段可以回归验证。
2. 只换视觉：风险较小，但难以达到「每项功能调整」和实用创新的目标。
3. 全栈重写：迁移成本与数据回归风险高，现有双运行方式和业务能力已有价值，本次不采用。

- 默认明亮工作台：雾白背景、白色内容面、石墨文字、蓝青强调色；暖金仅用于成就与重要进度。
- 保留可切换深色主题；成长解锁的配色映射为强调色，已有外观、伙伴、装备继续可用。
- 科幻感来自少量细线、进度刻度和伙伴插画。大面积网格、重复英文标签和强发光装饰让位于训练内容。
- 桌面左侧分组导航：训练（今日、错题、比赛）、分析（统计、知识）、个人（成长、伙伴）、设置。所有旧路由继续可达。
- 页面统一使用标题、简短说明、一个主要操作、局部分区。首屏优先显示可执行任务；角色图不占据主要操作区。
- 手机布局采用紧凑导航和单列操作；表格优先列保留，次要信息折叠。长代码允许容器内横向滚动，页面本身不溢出。
- 统一空态、失败重试、后台更新、未保存、已保存与禁用原因；读屏可识别状态，键盘可完成核心流程，减少动态效果设置有效。

## 五项实用创新

### A. 下一步训练导航

从已有今日题单中推导一条可执行建议：待评价 → 待写复盘 → 逾期复习 → 其他复习 → 新知。相同优先级保留原题单顺序。显示原因和原记录链接，不生成第二套任务、不改变每天最多 5+5 的上限。没有账号、目标未选、候选不足和全部完成分别提供对应入口。今日已生成题单稳定；新规划算法作用于用户确认的未来计划和后续新日题单。

### B. 可追溯的学习证据链

在题目详情集中呈现已有提交、尝试、复盘、提示、经验卡和迁移记录，并显示记录来源和时间。图谱、月报、诊断及成长记录回到同一题目或原记录；不存在的日期不推测，失效来源明确标记。无需 AI 即可查看，AI 解释仍是辅助材料。

### C. 可恢复的工作上下文

错题和比赛筛选进入 URL，前进、后退、刷新可恢复；快捷操作面板支持搜索页面与常用操作。复盘和解题工具切换保留现有草稿，离开前显示准确的保存状态和确认。此阶段不引入未设计过的数据自动保存机制，避免草稿覆盖正式笔记。

### D. ReAct 引导式学习复盘

ReAct 将模型的推理与工具行动交替组织，并利用工具反馈修正后续行动；本项目将其用于有证据、有检查点的复盘辅导。技术依据为 [ReAct 原论文](https://arxiv.org/abs/2210.03629) 和 [LangChain Agents 文档](https://docs.langchain.com/oss/javascript/langchain/agents)。以下学习流程和限制是本项目设计，不代表论文已验证算法竞赛学习收益。

入口覆盖题目详情的「带我复盘」、比赛报告的「带我复盘这场比赛」、今日训练的待复盘动作。统一使用现有星澪会话，页面显示精简的步骤、已查证依据、工具结果和下一步建议，不展示或保存模型内部推理。

| 阶段       | 用户实际体验                                   | ReAct 行动与依据                                                                   |
| ---------- | ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| 定位问题   | 选择题目/比赛，说明卡住的位置和这次目标        | 读取当前账号提交、已有笔记、尝试和上下文；缺代码或题意时明确补充项                 |
| 先自行回想 | 用户用自己的话说明思路、复杂度或失败假设       | 先提一个针对性问题；未请求完整解答时不直接灌输答案                                 |
| 查证与反馈 | 看到「已核对的记录」「待验证的猜测」           | 按需要调用题目资料、知识检索、代码分析或渐进提示；观察结果再决定下一步             |
| 验证理解   | 用户给出反例、解释关键不变量，或重新做题       | 对拍材料沿用下载/用户本地执行/报告导入；提交结果来自同步；没有执行证据不宣称已验证 |
| 沉淀复盘   | 得到错因、关键观察、修正思路、边界和复杂度草稿 | 引用实际证据，提示仍不确定处；已有笔记的修改先展示差异再确认                       |
| 迁移与再练 | 推荐适合的知识路径节点或迁移练习               | 调用确定性规划引擎获取候选与理由；安排新任务或修改未来题单沿用确认与撤回流程       |

**本轮必须新增的能力：**

- 结构化复盘工作流，阶段为 `orient / recall / investigate / verify / consolidate / transfer`；状态为 `ready / running / awaiting_input / awaiting_confirmation / completed / cancelled / failed / interrupted`。
- 保存目标、阶段、用户回答、工具动作摘要、证据引用、未验证事项和关联提案，刷新后继续；保存的是会话进度，不能自动写成有效复盘笔记。
- 每轮根据证据充分度决定继续查询、请求用户补充、提供下一层提示或结束。资料不足明确停止在等待输入，不编造题意、运行结果或外部成绩。
- 既有帮助记录沿用：查看资料不算提示，泄露解题思路/代码/对拍参考解按现有规则计入帮助；只有真实重做及用户评价能更新训练阶段。
- 原有「直接代码分析」等工具继续可用；用户可以跳过引导、结束会话或只保存草稿。
- 用户能看到行动进度并停止；保留外层 6 次模型/12 次工具/180 秒上限，叶子 AI 任务共用剩余截止时间与取消信号，不递归开启新的智能体。外层次数不伪称全部模型调用数，统计同时包含叶子任务。
- 账号切换、备份恢复、资料版本变动后重新校验证据和提案。重复确认必须幂等；中断的操作不会静默重放。
- 无工具调用能力的模型回到已有结构化分析入口；断网可读历史和用户进度，不假装完成 ReAct 查询。

**实际增量示例：** 用户复盘一道 TLE 题，系统先读取代码与提交记录并询问原先估计的复杂度；再按回答定位疑似瓶颈，提示构造边界数据。生成的对拍材料显示「待本地运行」，用户导入报告后才展示对应验证结果；最后形成待确认笔记，并根据学习路径推荐后续练习。用户未验证的推测始终标为推测。

### E. 自适应学习规划：知识追踪 + 先修路径 + 预算约束计划

目标是把「薄弱领域选题」发展为「从证据估计知识状态，找到通向目标的先修路线，再在可用时间内安排任务」。采用以下三个可独立测试的算法模块；这是现有算法在本项目中的组合应用，不宣称发明新算法，也不预先承诺学习收益。

| 模块         | 采用算法                                 | 输入与输出                                                                  | 用户能看到的价值                                       |
| ------------ | ---------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------ |
| 知识状态估计 | Bayesian Knowledge Tracing，BKT          | 独立重做/失败的时序证据 → 各知识点的掌握概率估计、样本与参数版本            | 区分没学过、证据不足、反复卡住、已有独立验证           |
| 学习路径     | 先修 DAG 的依赖闭包 + 带优先级的拓扑排序 | 用户目标、现有 prerequisites、知识状态 → 基础补足节点、下一节点与后续里程碑 | 明确为什么先补这个知识点，以及通向目标还差哪些步骤     |
| 学习计划生成 | 带数量/目标约束的 0/1 背包动态规划       | 路径候选、周目标、可用时间、必保留任务 → 未来题单及可解释的时间安排         | 在有限时间内兼顾复习、目标推进和适当挑战，减少无效堆题 |

BKT 选型依据：[pyBKT 研究论文](https://arxiv.org/abs/2105.00385) 与[研究团队实现](https://github.com/CAHLR/pyBKT)。DAG/背包算法依据：[MIT 6.006 课程讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-fall-2011/pages/lecture-notes/)。运行时用 TypeScript 实现小型纯函数，不引入 Python 服务、额外云端或强化学习训练管线。

#### E1. 知识状态：先有可信证据，再有个性化估计

- 从既有知识卡标签、人工确认的知识点标注连接题目与技能。只有八大领域而无具体技能映射时保留为领域证据，不擅自细分或把未标注 AtCoder 题塞进默认技能。
- 初版单技能 BKT 使用四个参数：先验掌握率 `L0`、学习转移率 `T`、猜对率 `G`、失误率 `S`。参数固定并带版本；起始建议 `L0=0.2, T=0.05, G=0.2, S=0.1`，作为未校准工程初值，不标为用户实测能力。
- 对可信正确/失败观察分别使用 `p(1-S)/(p(1-S)+(1-p)G)` 与 `pS/(pS+(1-p)(1-G))` 更新后验，再用 `p_next=p_posterior+(1-p_posterior)T` 更新学习状态。所有输入限制在合法范围，分母和极端概率有测试。
- 正确观察必须有该次 AC 和明确独立评价；失败来自明确的重做失败记录。提示后成功、仅有公开 AC、AI 诊断和聊天中的自称成功不作为独立正确观察。帮助记录仍可作为「需要再验证」的行动信号。
- 同一题/同一重做会话只计一次；对有多个知识点且无法归因的题，记录为混合证据，不向全部知识点重复投满额证据。提示后的失败也不与独立尝试混算。
- 少于 3 个不同题目的可信观察时显示「样本不足」，以原有领域规则和用户目标保守排序；无样本不得显示为已掌握。显示样本数、最近证据和初始参数未校准提示，不编造置信区间。
- BKT 估计是推荐信号，不替代既有五阶段「已掌握」状态，不修改成长经验，不把概率等同正式 Rating。标准 BKT 不建模遗忘，本轮保留既有间隔复习日期；逾期紧迫度单独纳入计划，不声称已预测记忆遗忘率。

#### E2. 学习路径：从目标反推必要基础

- 复用 `KnowledgeCard.prerequisites`，对选定目标节点求先修依赖闭包，再用优先级 Kahn 拓扑排序得到推荐顺序。需要同时满足的多个前置节点全部保留，不能用一条最短路径漏掉其他必要基础。
- 同层优先级依据目标关联、未验证程度、可解锁的后续节点与预计练习负担，确定性排序并保留评分说明。已具备可信独立证据的节点可折叠为「建议跳过」，用户可展开复查。
- 现有先修关系是可编辑的课程建议，不当成唯一数学事实。节点展示「建议先学」和来源，手动继续学习仍允许；AI 生成的新边只作为草稿，不能直接改图。
- 路径呈现为 3–7 个可见里程碑加完整列表，每节点包含知识卡、代表题、完成条件与后继；不是只画图，不以浏览卡片判定掌握。
- 若目录有环、悬空依赖、孤立目标或无适配题目，指出具体问题并降级到可访问知识卡与原规则训练，不递归卡死或补造题目。
- 路径按账号和目标保存，用户可调整目标；证据更新后给出「原路径/新路径/变更理由」预览，已完成节点不因重排消失。

#### E3. 计划生成：把目标放进时间预算

- 新增可选每日学习时长和目标知识节点；未填写时仍可按现有题量规则生成。成本优先用同类独立尝试的有效耗时中位数估计，样本不足使用明确标注的保守默认范围。页面不把估时写成完成承诺。
- 候选来自既有目录与个人复习队列。先处理待评价/待写复盘、已安排迁移和临期复习等保留项，剩余时间再安排新知；始终保留每栏最多 5 道、同日去重、新知未提交及历史不重复、平台难度口径独立等限制。
- 新知按当前难度区间筛选，满足先修可达性和周目标配额；有效候选充足时至少两道来自所选领域。现有用户已生成的今日题单不自动替换，算法启用从未来计划开始。
- 任务效用由知识缺口、目标相关度、先修解锁价值、适度挑战和主题覆盖组成，权重与算法版本记录。冷启动使用现有领域分数/难度规则；不拿未校准 BKT 给出虚假精确收益。
- 对候选先按可解释规则分层取至多 80 项（含所有必须保留项），时长向上按 5 分钟离散；DP 状态记录时间、复习数量、新知数量、已满足目标配额。默认预算支持 15–240 分钟；不设预算时以数量约束排序。该求解只对保留候选与离散模型最优，不宣称全题库全局最优。
- 时间不足以容纳必保留任务或周目标配额时，返回「约束冲突」及最小所需时间，不静默超预算、删掉已预约迁移或把题单标为成功生成。允许用户明确调整预算/未来安排后重算；失败保留旧计划。
- 学习路径、候选和成本估计发生变化只生成未来版本；确认后写入，支持版本对比和撤回。原有自动调整开关仍默认关闭，开启后也不修改今日，不跨账号写入。
- 原有学习 Agent 和 ReAct 均调用同一个规划引擎：模型负责解释用户目标、提出候选偏好和讲解结果，最终候选合法性、预算、配额与落盘由确定性模块决定。
- 每道推荐提供「为何选它、与目标的关系、预计时间、替代候选」；换题只在未生效的未来预览里进行，再运行完整约束校验，避免破坏今日稳定性。

#### E4. 怎样验证“更加高效”

1. **算法正确性：** BKT 手算样例、乱序/去重/提示污染；DAG 环检测、依赖全覆盖；DP 与小规模穷举交叉校验；同输入与版本返回同结果。
2. **计划可用性：** 冷启动、仅 CF、仅 AtCoder、无可用新知、短预算、冲突目标、重复题、跨周和离线都能给出计划或明确可操作原因。
3. **历史回放：** 按时间截断证据和当时可知的目录，对比旧规则与新算法的约束满足率、超时预算率、知识覆盖和下一次独立表现预测校准；禁止把未来记录泄漏到过去推荐。历史目录不足时标注不可比，不拿当前题库伪造过去。
4. **实际学习效果：** 本地记录计划来源/算法版本/采纳情况，用后续真实数据展示独立完成率、提示依赖、复习逾期积压、迁移完成率和单位有效训练时间的独立完成数量。仅看做题量不能证明效率。
5. **结论边界：** 自动验收证明算法与流程可用；没有持续使用数据前，报告「效果待观察」，不承诺提升百分比。历史对照受用户选题等因素影响，不当作因果证据。

## ReAct 与规划引擎的衔接

用户目标 → 本地知识追踪 → 先修路径 → 时间预算计划 → 真实训练 → ReAct 引导复盘 → 经用户确认的记录与独立重做证据 → 更新未来路径和计划。

只有真实学习证据进入知识状态；AI 草稿与行动建议进入待确认区。所有推荐都能跳到依据，所有持久化变更都使用账号范围、数据版本和幂等保护。基础规划和证据浏览离线可用，ReAct 调用模型时才需要网络及用户配置。
