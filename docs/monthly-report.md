# 月度算法报告

入口：**训练统计 → 月度报告**。默认当月，支持历史月份和 CF / AtCoder 来源切换；两站合计额外列出绑定的 XCPC 队伍比赛。

## 指标口径

- 按北京时间 `[月初, 次月月初)` 归集，当月截到当前；提交按平台和 ID 去重，题目按平台和题目标识去重。包含只 AC、未进入错题本的题目。
- 尝试题数：月内有提交的题目；通过题数：月内有 AC 的题目；首次通过：已保存的最早 AC 发生在本月。没有成功全量同步时，显示“已导入记录中的首次通过”。
- 提交分为 AC、明确失败、待评测、其他；待评测及系统状态不当作失败。通过率只使用 AC 与明确失败提交，重复 AC 也计入。
- 活跃天数取提交、重做评价、提示使用、迁移评价的日期并集。复习题单按日期与题目去重；多级提示按练习会话去重。重做、提示、迁移可能描述同一次练习，单列展示，不相加计总量。
- 比赛按开始时间归月：正式、虚拟、其他确认参赛计入总数，AtCoder 仅赛时提交单列。缺少开始时间不计数，不能拿官方历史中的结束时间补成开始时间。CF 虚拟使用已记录的虚拟开场时间；手动模拟使用会话开始时间。同一比赛仅计一次，正式优先于虚拟，再优先于其他和仅赛时提交。
- XCPC 只统计队伍成绩，不增加个人提交或做题量。各平台 Rating 不合并；已有评分沿用原报告，当前补题完成状态可能发生在报告月之后。
- 当月比较上月相同已过时长，短月份截到月末；历史月份比较前一完整月份。无基准不生成增长率，单项基准为零时只显示差值。

## 分析与接口

规则分析离线可用，涵盖数量、连续性、提交通过、复习、失败题标签、当月错因快照及比赛补题，均附证据和行动建议。题目标签只提示相关性，AC 不代表掌握。旧笔记没有当月快照时，不假定错因在该月产生。

- `GET /statistics/monthly?month=YYYY-MM&source=all|cf|atcoder`：月份可省略，默认北京时间当月；拒绝未来月份。
- `POST /learning/monthly-report`：请求 `{month, source, fingerprint}`，服务重新生成证据，不接受客户端伪造统计。返回附证据 ID 的 AI 解读；无效引用、异常格式、模型错误、账号切换、恢复或期间数据变化均拒绝结果，页面保留规则分析。
- 切换月份、来源、账号、保存训练反馈、完成同步或窗口重新聚焦后刷新报告；也可点击“刷新报告”。AI 解读仅供本次查看，不存储月度档案，备份继续使用 v8。

## 验证

固定模型、内存数据库与两种浏览器适配分别验证月界、去重、首次 AC、参赛证据、复习与提示、错因来源、跨账号迟到响应和报告变化。手机验收使用 390px 宽度，确认没有横向溢出。

真实模型检查：`node --import tsx scripts/verify-monthly-live.ts [数据库路径]`。仅读取保存的模型配置，使用内存中的合成提交，不发送个人训练数据，不写业务数据库，也不输出密钥。没有配置时明确返回 `UNAVAILABLE`，不能视为模型验收通过。

2026-10-08 验证结果：新增月报单测 12/12；全量单测 100 通过、1 项既有对拍环境测试跳过。本地完整浏览器回归 18/18；Pages 18 通过、3 项既有配置跳过。最终月报流程在两种构建各复验 2/2，Pages 包含断网刷新。类型检查、两种构建与差异格式检查通过。真实模型检查返回 `UNAVAILABLE`，本地没有保存 AI 配置；未提交或发布。
