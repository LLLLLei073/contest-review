# 自动比赛复盘

打开「比赛复盘」，选择 Codeforces 比赛。首次查看会自动读取官方榜单、评级记录、题目难度和该用户的比赛提交。数据保存在当前浏览器（本地版保存在 SQLite），再次打开和离线查看不需要重新下载。刷新分析会核对判定；失败时保留已有报告和笔记。

在「设置」中还可按姓名搜索 XCPC Rating 选手，核对学校后绑定。两个来源独立绑定；更换选手后旧选手的报告和笔记仍保留在本机。比赛列表可按来源筛选，也可切换 XCPC 官方计分场次与全部场次（含星标场次）。「一键复盘」先同步已绑定来源，再补齐尚未生成的比赛报告；中断或失败后重新点击可继续未完成的部分。

## 数据口径

- 正式、非正式、虚拟分别计算，多次虚拟按开始时间拆分。只有练习记录不评分。
- 赛时窗口为开始时间（含）到开始时间加比赛时长（不含）。时间线使用提交创建时间，虚拟场次使用虚拟开始时间。
- 赛后补题不增加赛时成绩。评分只认识最近获取的判定，不能还原过去的评测状态。
- 榜单只请求 `contest.standings?contestId=...`；所有公开请求共用串行队列，间隔至少 2.1 秒。完整榜单较大，首次分析可能需要等待。
- 排名采用当前榜单个人正式参赛者的顺序；同分同排名采用并列中位位置。不混用评级结算排名。团队和 ghost 不进入个人对照。
- 数据未终结、冻结或存在未知判定时显示暂定结果。缺失比赛时间、未完成提交导入或团队参赛不生成个人综合分。
- 旧版数据库自动迁移。新备份版本为 v3，支持恢复 v1/v2；旧版应用不能读取 v3。恢复前仍会自动备份。

## XCPC Rating 报告

XCPC 报告直接展示 [XCPC Rating](https://hei-maom.github.io/xcpcrating/#/) 提供的表现分、名次、解题数及比赛题目信息。它与本站预估 CF 表现分都以 Rating 数值展示，但来源、参赛人群和评分体系不同，不能直接换算；百分制综合复盘分又是另一项指标。列表中的场次与绑定选手的历史记录对应，同名选手须凭学校区分。

## 本站预估 CF 表现分 v1.0

本指标回答“这场发挥大约相当于多少 CF Rating”，不是 Codeforces 官方给出的表现分或赛后 Rating 变化。仅在比赛已结束、榜单未封、个人参赛、赛时提交完整且判定明确时计算；练习与团队参赛不计算。结果取整数，超出 0–4000 的显示范围时仅显示 `≤0` 或 `≥4000`。

- 正式评级赛优先用同场有有效赛前 Rating 的个人选手作对照，至少 20 名其他选手。`seed(R)=1+Σ[1/(1+10^((R−对手赛前Rating)/400))]`；实际名次只在该对照群内计数，并列取中位位置；目标名次 `m=√(seed(本人赛前Rating)×实际名次)`，再二分求 `seed(表现分)=m`。这与 XCPC Rating 公开的“预期名次—几何平均—反推表现分”步骤同类，但没有对两套 Rating 做跨平台标定。
- 虚拟赛、非评级赛、缺少赛前 Rating 或同场对照不足时，若完整题集中至少 3 题有难度且覆盖率达到 80%，按题目难度估计各题 AC 概率，反求与赛时完成数匹配的 Rating。目标完成数为 `有难度题数×(AC数+0.5)/(有难度题数+1)`，使零 AC 和全 AC 保持有限值。此法标为“低置信度·难度估算”，并非 XCPC 的名次反推公式。

分析缓存仍保存原始榜单和评级数据，读出时重新计算本指标；已有笔记和 v1–v3 备份无需迁移。刷新后的重判结果会改变赛时 AC 与估算值。

公开数据没有完整的个人赛时提交记录，因此 XCPC 页面不伪造逐次提交时间线，也不把团队表现描述成个人提交。建议由来源成绩、预测值和该选手过往同等级比赛记录按固定规则生成，展示所用事实；样本不足时只展示可核实的结果。自动刷新失败会保留已缓存的报告和补充笔记。离线时可查看已有报告。

## 算法 v1.0

所有分项限制为 0–100，合成后才四舍五入。本站评分为可解释的复盘指标，不是 CF Rating，也不用于跨用户实力排名。

| 分项         | 权重 | 规则                                                                                                                                                                                                                                                        |
| ------------ | ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 排名相对发挥 | 35%  | `70 + 100 × (本场超越比例 − 对照组超越比例中位数)`。对照组赛前 Rating 相差不超过 200，排除自己，至少 20 人。                                                                                                                                                |
| 难度完成情况 | 30%  | `70 × 有难度题AC数 / Σp`，`p=1/(1+10^((难度−赛前Rating)/400))`。经验规则，需要完整题集、至少 80% 难度覆盖和正数赛前 Rating。                                                                                                                                |
| 提交稳定性   | 20%  | `100 × A/(A+F)`。A 为赛时 AC 题数，F 为首次 AC 前及未 AC 题的明确失败次数；重复 AC 和首次 AC 后的失败不增加计分失败。                                                                                                                                       |
| 推进节奏     | 15%  | `70 + 100 × (历史T中位数−本场T)`，`T=(首次AC时间+达到最终AC数一半时的时间)/(2×时长)`。半数向上取整。取此前最近最多 10 场有效、同参赛类型、同计分制、时长相差不超过 25% 的比赛，至少 3 场；零 AC 历史无法产生 T，不纳入样本。本场零 AC 且历史有效时计 0 分。 |

正式比赛优先使用本场 oldRating，其他场次使用开始前最近一次评级结果。无有效 Rating 时不推测个人水平。题目难度是本次接口给出的难度，不声称是比赛当时发布的难度。IOI 部分分数保留官方展示，难度项只算完整 AC。

全部分项齐全时给完整综合分；有效权重至少 65% 且包含排名或难度时按有效权重归一化，标为暂估分；否则仅展示事实和可用分项。缺失项不按零分处理。历史比赛必须在本场开始之前已结束，不混入未来比赛；没有完整历史同步时不建立节奏基线。不同有效分项的总分不进行历史分差比较。

## 建议

建议固定按规则生成，最多五条，每条展示观察、可能原因、行动和证据链接。依次检查重复失败（同题至少 3 次）、连续失败跨度（至少比赛时长 20%）、CE/RE（至少 2 次）、TLE/MLE（至少 2 次）、低于赛前 Rating 的未 AC 题（最多 2 题）、排名/节奏相对基线落后超过 0.1。

连续失败链遇到 AC、待判或未知状态即中断；跨度不是思考时长。未提交题仅列为补题候选，不自动加入错题库。无具体证据时不推断负面原因；成功且首次 AC 前无失败时给有证据的正向反馈。

## 验证

- `npm test`：固定数据验证公式、时间边界、重判、虚拟场次、对照缺失、数据迁移和失败缓存保护。
- `npm run test:e2e` / `npm run test:pages`：自动报告、笔记、备份；Pages 另验证离线查看和真实网络错误路径（固定接口样例）。
- `npx tsx scripts/check-contest-analysis.ts 2000`：独立调用真实官方接口，在内存中选择榜单中的一个个人参赛者，核对排名、赛前 Rating 和赛时窗口。结果写入被 Git 忽略的测试目录，不影响个人数据。
